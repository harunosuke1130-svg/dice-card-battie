# 六耀の決闘 — 個別HP・前衛・属性版

8体から異なる5体を編成してCPUと対戦する日本語のカードバトル。数字を先に確定し、生存キャラからその数字の通常技を使う1体を選びます。

## 遊ぶ

- GitHub Pages：既存の公開設定 `codex/rokuyo-web` ブランチの `/docs` をそのまま使用します。公開設定・URLを変更する必要はありません。
- ダウンロード：`downloads/rokuyo-duel.html` をSafariで開くだけで遊べます。通信・追加ソフト・サーバー起動は不要です。CSS・JavaScriptを内蔵し、Mac標準の日本語フォントを使用します。

## 個別HPと前衛

各キャラがHPを持ち、共通HPはありません。剣士120、巫女100、射手95、守人160、魔術師100、薬師110、渡り鳥105、旅人130。

編成後、プレイヤーは最初の前衛を選びます。CPUの最初の前衛は自チームの生存キャラのHPから選び、プレイヤーの未確定の選択には依存しません。

通常技を確定すると使用者が前衛に残り、次の敵の攻撃を受けます。通常攻撃・直接攻撃スキルの対象は敵の前衛のみです。選び直すだけでは前衛も数字も変わりません。交代しても減ったHPはそのままで、HP0のキャラは出場・通常技・スキル・回復対象にできません。

前衛が倒れたら後任を選びます。選択による攻撃・ターン消費・CD減少はありません。通常技で倒れた場合は後任選択後に相手のターンへ進み、スキルで倒れた場合は後任選択後に同じ数字・スキル使用済み状態で通常技の選択へ戻ります。敵5体すべてが戦闘不能になると勝利です。

回復は生存している味方1体を指定でき、控えも選べます。結界も指定した1体に紐づき、交代で移動せず、次の防御可能なダメージ1回まで継続します。防御無視スキルでは消費されません。スキル使用だけで前衛は交代しません。攻撃強化はそのターンの次の通常技に有効で、スキル使用者とは別のキャラにも使えます。

1ターン1スキル・本人のターン開始時だけCDが1減るルール、通常技6つ、既存スキルの数値とCDを維持しています。16巡目からの回復疲労も維持し、前衛・控えの回復に同条件で適用します。再戦でHP・CD・結界・攻撃強化・疲労を初期化します。

## 属性

水→火、火→自然、自然→水、聖光→呪闇、呪闇→聖光の通常技のみ1.05倍。それ以外・未知の属性の組み合わせは1倍で、不利による減衰はありません。

通常技の基礎ダメージに攻撃強化、属性倍率、防御効果の順で適用し、最後に1回だけ四捨五入します。通常40なら有利時42。固有スキル・固定ダメージ・回復には属性倍率を適用しません。副属性は自由に追加できる文字列配列で、表示分類のみです。

## 編集する場所

`src/game.js`：

- `CARDS`：名前、外観、出目1〜6順の通常技。`damage` と `heal`。通常技に `fixed: true` を付けると属性倍率の対象外になります。
- `SKILLS`：`CARDS` と同順の固有スキル。数値、説明、`cooldown`、各効果。
- `PROFILES`：同順の `maxHp`、`element`、`tags`。新属性と副属性キーワードはここへ追加できます。
- `AFFINITY`：`bonus` が有利倍率の唯一の設定値。`advantages` が有利の方向。画面のルール・倍率表示もこの値を参照します。
- `members`：キャラ別現在HPと結界。`front`：各側の前衛位置。
- `selectFront`、`resolve`：初期前衛と戦闘不能時の後任・進行再開。
- `previewNormal`：攻撃強化→属性→防御→四捨五入。画面の実効威力と実処理で共通利用。
- `actionChoice`、`skillChoice`：生存キャラと公開されている戦闘状態だけを使うCPU判断。

`src/app.js` は画面・対象選択・ログ・非同期演出、`style.css` はレイアウトです。

```sh
python3 scripts/bundle.py
```

ソース変更後、単一HTML版と `docs/index.html` を同内容で再生成します。

## 開発と検証

```sh
npm test
node scripts/balance.mjs
npm start
```

Node標準テスト19件に、100戦のCPU同士の自然な全滅までの進行も含みます。出目対応、HP保持、被弾先、KO制限、初期前衛と後任、スキルKO後の再開、属性倍率と丸め、回復・結界対象、CD、全滅、初期化を検証します。

`balance.mjs` はシード1〜500とランダム編成を使い、バランス・攻撃・回復優先を各500戦検証します。スキルは全方針で共通のAIです。後任は自チームのHP最大の生存キャラを選びます。最新結果は `reports/balance.json`、旧共通HP300版の結果は履歴として `reports/hp300-balance.json` に分けています。

個別HP版1,500戦は全滅まで終了しました。平均プレイヤーターンはバランス25.16、攻撃優先24.52、回復優先30.44、最長55。共通HP版と異なり、5体を倒すため対戦は長くなっています。これはシミュレーション結果で、人間のプレイ時間や全ての戦略での終了を保証しません。

Playwrightを用意した検証環境では `node scripts/browser-check.mjs` を実行できます。別の場所に導入済みの場合は `PLAYWRIGHT_MODULE`（モジュールのfile URL）と `CHROMIUM_PATH`（実行ファイル）を指定します。確認用にメモリー上のテストHTMLへ状態参照と演出短縮を注入し、初期前衛、対象回復、連打、KO後の後任、全滅、再戦、スマートフォン幅とPC幅、外部通信0件を検証します。HPを変更しない通常対戦も1戦完走させます。公開HTMLにテスト用の状態参照は含みません。Safari実機での操作検証は別途必要です。

公開は同じブランチの `/docs` を更新する方式です。push成功・リモートのコミット一致と、GitHub Pagesのデプロイ完了・公開URLからの配信確認は別の検証結果として扱います。サイトはURLを知る第三者がアクセスでき、ログインやアクセス制限はありません。戦闘状態は各ブラウザのメモリー内で処理します。
